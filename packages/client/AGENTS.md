# AGENTS.md

## Workspace

- This directory is `@toyota/client`, a private, source-only typed HTTP SDK inside the pnpm/Turbo workspace at `../..`.
- It talks to `apps/server` (package `api`) over HTTP only. Do not import from `apps/*` or other workspace packages, and do not pull browser/engine UI code into the SDK.
- No build step: `main`, `types`, and `exports` all point at `src/index.ts`.

## Agent constraints

- The agent shall only write code. All scripts are run manually by the user — dev servers, builds, typechecks, tests, linting, formatting, codegen, DB setup/migrations, and seeders. Command sections below are reference only.

## Commands

- `pnpm check-types`, `pnpm format`. There is no build, lint, or test script.
- Regenerate API types from the workspace root with `pnpm generate:api`: it emits `apps/server/openapi.json` and then runs `pnpm --filter @toyota/client generate:types`.
- `pnpm generate:types:remote` uses `${API_BASE_URL:-http://localhost:3000}/api-docs.json`; only use it when a server is running locally.

## Architecture

- `src/api/generated/api.types.ts` is generated by `openapi-typescript`. Never edit it by hand: change the server schemas and regenerate. Only `components` and `paths` are re-exported from `src/index.ts`.
- `api/api.config.ts` holds module-level config validated with Zod. `configureApi()` must run at app startup before any client call; `getApiConfig()` throws otherwise, and `resetApiConfig()` is for tests.
- `api/api.types.ts` derives the JSON:API envelope and resource types from generated schemas. `api/index.ts` defines `BaseApiClient`, `defaultHeaders`, `withIdempotencyKey()` (`Idempotency-Key`), and `unpackSingle`/`unpackCollection`, which throw `createUnpackError` on malformed envelopes.
- `api/clients/{catalog,missions,tanks}.api.ts` define one client per endpoint group, exported as lazy `Proxy` singletons so config is read at first use rather than module load. New endpoint groups should follow this shape and be re-exported from `src/index.ts`.
- `axios/axios.core.ts` de-duplicates refreshes through `refreshPromise`. On the server it updates the cookie provider and instance `Cookie` header but deliberately retains `outboundCookies` so `Set-Cookie` can be propagated. `executeRequest` unwraps 204 responses to `undefined`.
- `axios/axios.interceptors.ts` injects SSR cookies, collects `Set-Cookie`, auto-refreshes on 401 behind an `_isRetry` guard (a 401 from the refresh endpoint is fatal), maps timeouts to `TimeoutError`, and reports network/5xx failures to Sentry in browsers only.
- `axios/axios.sentry.ts` dynamically imports `@sentry/react`; `axios/axios.utils.ts` holds cookie parsing/merging and base config helpers; `axios/axios.types.ts` augments axios config with `_isRetry`.

## Gotchas

- The `apps/api/src/lib/idempotency/...` path in the `api/index.ts` comment is stale; the backend lives in `apps/server`.
- Do not call `getApiConfig()` or instantiate endpoint clients at module scope: it breaks SSR and tests.
- Keep generated types read-only, and prefer focused `pnpm exec prettier --write <files>` over `pnpm format`.
